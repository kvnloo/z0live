# C1-r6 — preregistration (written and frozen before any arm was run on the r6 cohort)

Second fresh holdout for the C1 warm-route candidate **V1** (value-preserving sem-r3 trim), with scenario text written by a **different author** than the V1 lexicon, plus a **pre-registered benefit metric** (warm vs exact r4). CPU only, stdlib `python3 -I`, no model, no network at scoring time. Scored once, on GitHub Actions (`kvnloo/z0live`, branch `ci/c1-r6`). No production default is changed; V1 is a test-only monkey-patch of `brief_compress_sem3.trim_exchange` in the harness (as in r5).

**What C1-trim-r5 left open, and what r6 changes for each (read from `../C1-trim-r5/RESULT.md` and the ledger row).**
1. *The r5 generator and the V1 lexicon share an author, so the pass may be fitted to that phrasing.* r6: all scenario wording (update/restate templates for every fact kind, static statements, probe questions, topic nouns/items, object/event phrases, names, places, colours, codewords, code stems) comes from free-pool LLMs that were given only the structural schema (`author/author_prompt.md`, `author/prompt_p*.txt`): fields, probe/value structure, fact kinds incl. names/places/codewords/colours/digits, the N7 shape ("value in its own non-digit sentence before a digit sentence"), supersession pairs, zero-probe control. They were NOT given the V1 lexicon, the V1 code, or any word about trimming or filler (checked: 0 matches for filler/lexicon/trim/compress/V1 in every author prompt). The planned author `codex exec -m gpt-6.2-sol` was not possible: no `codex` binary exists on this host. Fallback is the free pool `vllm-sr/free-quality` (router; the serving model is whatever the router picks per call; per-call model ids are recorded in `raw/author/response_p*.json`). Structure stays with me: kind mix/weights, per-scenario counts, day/time/number draws and the seeded template choice are fixed by the deterministic script `c1_r6.py` (seed **20261130**) exactly as in r5.
2. *No benefit of the warm route over r4 was measured.* r6 pre-registers the metric and rule below.

**Arms.** **A** = exact r4 (`vendor/baseline_r4.py`, pinned). **B1** = sem-r3 + V1. The V1 code is **not re-typed**: `c1_r6.py` extracts lines 34-99 of the pinned r5 harness (`vendor/c1_trim_r5_harness.py`, sha256 ee5a83ab…) and asserts the block sha256 `e0ec860b…f220` before `exec` (byte-identical to r5 by construction; assert in code). **B0** = unmodified sem-r3 (`vendor/brief_compress_sem3.py`), report-only (also gives the trim-exercised control). V2 is dropped. States per arm: **fully-cached warm** and **controlled key-miss** (last candidate key withheld; must fall back to r4 at preflight with 0 synchronous key/pair attempts). No after-the-fact guard anywhere.

**Cohort r6 (M, `stats`; compressor never run on it).** 17 scenarios (16 probe-bearing + 1 zero-probe route/repeat control = r6/17), **112 probes, 85 non-digit current values** (27 digit), budget 2810. Same fixture schema and `prior.render` (16 noise lines). Fact kinds as in r5: D1-D3 digit-labelled; N1 leading `Name:` label; N2 name in a clause before the digit clause; N3p place; N3c codeword; N4 colour; N5 no digit; N6 name label + place; N7 name in its own non-digit sentence before the digit sentence; statics S1-S5. The merge step (`c1_r6.py merge`) validates each author template against its kind's schema (placeholders, positions) and drops invalid ones; pool values that collide with other pools, with topic/thing words, with the fixed noise sentence, or with the V1 filler word list are dropped (structural check the r5 harness already required; **0 dropped here**). Fixture build asserts that no statement carries another statement's value.

**Author-run disclosure.** Parts p1-p5 (pairs D1-N3p; N3c-N7; statics+asks; word lists; N1 redo). Failed attempts are kept in `raw/author/*.failed*`: p2 attempt 1 closed its JSON one brace short, attempts 2-3 returned empty/truncated output (different routed models), attempt 4 was used; p1's N1 templates wrote literal first names instead of `{V}` (0/8 valid), so N1 was re-requested once (p5) with an explicit placeholder instruction and the p5 output replaces p1's N1. The merge repairs only a missing closing brace (mechanical, logged to stderr; p5 needed one `}`), never content. No template was edited by hand.

**Design history (disclosed).** The harness was derived from the r5 harness. The only checks run before freezing: `merge`, `stats`, `build` on the r6 seed (render/parse/hash, no compression), and a **dev-mode dry replay on the already-scored r5 fixtures** (never on r6): reproduces the r5 numbers for B0 (22 warm losses) and B1 (0 losses, warm kept 16/17), and, on r5, B1's warm briefs were *larger* than r4's in 15/16 scenarios (total 41990 vs 40866 chars) while exposing far fewer superseded values (2 vs 66). I therefore expect (I) the primary size rule below to FAIL and the stale count to improve; the rule was fixed from the task statement before that look at the metric's behaviour and is **not** changed. V1 was never run on the r6 cohort before freezing.

**Primary gates (per B1, both states, whole-token match as in r2-r5).** New loss = A holds the probe's current value and B1 does not. PASS(no-loss) needs: **B1 warm losses = 0 AND key-miss losses = 0 AND warm kept ≥ 12/17** AND every warm brief fits the budget (≤ 2810 chars, starts `Context`). "Warm kept" (stricter than r4, no fallback in these arms): warm run is not an r4 fallback and its brief differs from exact r4.

**Controls (any failure ⇒ NULL(harness)).** (1) Known-loss control: forced-empty output counts a loss in every probe-bearing scenario (16/16; harness asserts). (2) Key-miss output equals r4 in 17/17, B1 and B0. (3) Sync key attempts 0 and sync pair attempts 0 in both states, B1 and B0. (4) Unguarded-miss control (preflight off, key withheld) detects a synchronous key attempt in 17/17 (assert). (5) A/A and B/B repeats: 0 flips, outputs byte-equal (A, B1, B0, warm and key-miss). (6) Trim branch exercised by unmodified sem-r3 (B0, `info.trimmed` non-empty) in **≥ 8** scenarios. (7) Hash check of fixtures, harness, PREREG, author inputs and all vendored sources against `FREEZE.txt` (checked by `sha256sum -c` in the job and again by the harness before scoring). (8) V1 block sha256 assert (above). Budget overflow 0.

**Benefit metric (pre-registered, exact).** Over the **16 probe-bearing scenarios** (the zero-probe control is excluded because no supersession exists there), warm state, B1 vs A (exact r4):
- size: `d_i = len(A_i) − len(B1_i)` in chars (positive = B1 smaller);
- stale exposure: `s_X,i` = number of distinct superseded values (the union of `superseded` values over scenario i's probes) that appear whole-token in brief X (`prior.has`);
- scenario i is **better** iff `d_i > 0` OR `s_B1,i < s_A,i`.
**BENEFIT-PASS iff median(d_i) > 0 AND (number of better scenarios) ≥ 10 of 16.** Otherwise BENEFIT-FAIL. Reported, not part of the rule: mean d, scenarios smaller/larger, scenarios with fewer/more stale, totals of chars and stale values, scenarios worse (larger or more stale). Secondary informational line (does not change the verdict): total stale exposures and scenarios with fewer stale.

**Verdict (frozen).**
- Gate NULL(harness) / FAIL(loss) (any B1 loss in either state or a warm brief over budget) / FAIL(degenerate) (0 losses but warm kept < 12/17): benefit not scored as a verdict; V1 is not a candidate on this evidence.
- Gate PASS(no-loss) and BENEFIT-PASS ⇒ **`PASS(holdout) BENEFIT-PASS`**: V1 stays the C1 warm-route candidate with a measured benefit (still draft/opt-in; no deploy).
- Gate PASS(no-loss) and BENEFIT-FAIL ⇒ **`PASS(no-loss) BENEFIT-FAIL`**: r4 stays the default; the warm route has no benefit on this metric (stale-only reductions are reported but are not a pass).
One scored run; no retuning, no exclusions; a harness stop is NULL(harness), not re-run with changed gates. Result is commented on draft PR #194 whichever way it falls.

**Limits.** Synthetic cache and keys; no live readiness, wall-time or answer-quality claim. Author is a router of free open models (identities vary per call, recorded), prompted from my schema; N7 count is whatever the seed drew (4 pairs). The structural kind mix is mine, not the author's. One cohort, one seed. A PASS is evidence on a second holdout, not production approval.
