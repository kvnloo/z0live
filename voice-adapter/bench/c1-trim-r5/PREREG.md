# C1-trim-r5 — preregistration (written and frozen before any variant was run on the r5 cohort)

Fresh synthetic holdout **r5** for two fixes **inside** the sem-r3 level-3 trim. CPU only, stdlib `python3 -I`, no model, no network. Scored once, on GitHub Actions (`kvnloo/z0live`, branch `ci/c1-trim-r5`). No production default is changed: both variants are test-only monkey-patches of `brief_compress_sem3.trim_exchange` in the harness.

**Why.** `C1-fixtures-r4`: the r3 digit-only after-the-fact guard lost 10/110 non-digit values (names in a leading `Name:` label, place words in a clause before the digit clause) and kept the warm route in only 9/17; a labelled-value "any-value" guard would keep 4/17 (degenerate). The fix has to be inside the trim.

**Arms (one change per variant).**
- **A** = exact r4 (`vendor/baseline_r4.py`, pinned).
- **B0** = unmodified sem-r3 (`vendor/brief_compress_sem3.py` @38686df). Report-only reference, not a verdict arm.
- **B1 = V1 "value-preserving trim"**: `trim_exchange` replaced. Levels 1-2 (asker sentence + reply / sentence alone) are accepted only if every asker-line token they drop is a single filler word (`FILLER_WORDS`). Level 3 is no longer "the clause holding the last digit word"; it is the asker sentence with only filler phrases/words removed (`FILLER_PHRASES`, `FILLER_WORDS`), accepted only if every asker-line token missing from it is one of the removed filler tokens. Every other token (leading `X:` labels, capitalised names/places, codewords, colours, digit words, nouns, verbs) is kept in order. If no level fits the slot (+ SLACK 8), sem-r3's existing "untrimmed" path applies (line stays at its own position and size). The lexicon was written before the r5 cohort was generated and is frozen (hash in `FREEZE.txt`); an unlisted word is treated as value-bearing and never dropped.
- **B2 = V2 "level-3 off on the warm route"**: sem-r3's own `trim_levels`, levels 1-2 only.
No after-the-fact guard in any arm. States per arm: **fully-cached warm** and **controlled key-miss** (last candidate key withheld; must fall back to r4 at preflight with 0 synchronous key/pair attempts).

**Cohort r5 (M, from `stats`; the compressor has not been run on it).** Generator `c1_trim_r5.py` (seed **20261129**; new topic nouns, object/event nouns, digit-stem, name, place, colour and codeword pools; new templates; written fresh, nothing copied from r2-r4). 17 scenarios (16 probe-bearing + 1 zero-probe route/repeat control = r5/17), **112 probes, 80 non-digit current values** (32 digit). Same fixture schema and `prior.render` (16 noise lines), budget **2810**. Fact kinds: D1-D3 digit-labelled; N1 leading `Name:` label + digit clause; N2 name in a clause before the digit clause; N3p place and N3c codeword before the digit clause; N4 colour before the digit clause; N5 no digit (non-candidate); N6 name label + place before the digit clause; **N7 name in its own non-digit sentence before the digit sentence** (statement-level hazard for levels 1-2); statics S1-S5. Build runs only render/parse/hash (no compression).

**Design history (disclosed).** V1/V2 and the harness were debugged on the r4 cohort (now a DEV set) and on three throw-away dev seeds (7, 8, 9) of this generator, never on seed 20261129. Dev results (M): r4 cohort: B0 31 warm losses, B1 0, B2 0; dev seeds 7/8/9: B0 33/33/27, B1 0/0/0, B2 5/5/3. The N7 kind was added after a first dev pass showed B2 with 0 losses on a generator without it; V1's level-3 token check was added during the same dev loop. My prior (I): V1 passes, V2 fails on N7-type values. These are priors, not results.

**Primary (per variant, both states, whole-token match as in r2-r4).** New loss = A holds the probe's current value and the variant does not. PASS needs **0 new losses** AND **warm route kept in >= 12/17 scenarios** AND every warm brief **fits the budget (<= 2810 chars, starts `Context`)**.
"Keeps the warm route" (stated now, stricter than r4 because there is no fallback in these arms): the warm run is not an r4 fallback **and its brief differs from exact r4** (a route that returns r4 bytes is not doing the warm work). Also reported: briefs changed vs r4, scenarios where the variant trimmed, untrimmed lines.

**Controls (any failure => NULL(harness) for both variants).** (1) Known-loss control: forced-empty output counts a loss on every probe-bearing scenario (16/16). (2) Key-miss output equals r4 in 17/17, per variant. (3) Sync key attempts 0 and sync pair attempts 0 in both states, per variant. (4) Unguarded-miss control (preflight off, key withheld) detects a synchronous key attempt in 17/17. (5) A/A and B/B repeat: 0 flips (A, each variant, warm and key-miss; outputs byte-equal). (6) Trim branch exercised by unmodified sem-r3 (B0, `info.trimmed` non-empty) in **>= 8** scenarios, else NULL(harness). (7) Hash check of fixtures, harness, PREREG and all vendored sources against `FREEZE.txt` before scoring. The harness raises on any integrity or route assertion.

**Verdict per variant.** `PASS(holdout)` | `FAIL(loss)` (any new loss in either state, or a warm brief over budget) | `FAIL(degenerate)` (0 losses but warm kept < 12/17) | `NULL(harness)` (controls above).

**Decision rule (stated now).** If a variant passes it becomes the C1 warm-route **candidate** (draft PR to staging behind an opt-in flag only; no deploy, no default change). If both pass, both are recorded as candidates and V2 (the simpler change) is named first; the PR draft carries only the one named first. If neither passes, recommend closing the warm route (r4-only C1 default). One scored run only; no retuning, no exclusions; a harness stop is reported as NULL(harness), not re-run with changed gates.

**Limits.** Synthetic cache and keys; no live readiness, wall-time or answer-quality claim. Author-written templates (the lexicon and the generator have the same author, so V1 may be unfairly matched to this phrasing; unlisted fillers are simply kept). One cohort, one seed. A PASS is evidence on one holdout, not production approval.
